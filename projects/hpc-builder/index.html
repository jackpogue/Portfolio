Deploying large HPC clusters from a thumb drive

I created a menu-driven installation system that transformed a thumb drive or DVD and a room of unconfigured, OS-free bare-metal servers into a functioning cluster in less than two hours.

My responsibility
Designer and implementer

Starting point

Outcome
Large operational clusters in less than two hours

From unconfigured bare metal to an operational HPC

A pile of servers is not an HPC. Every node still needed an identity, network configuration, boot service, consistent image, shared services, security controls, monitoring and auditing, and a reliable way to join the cluster.

I built a menu-driven configuration system that started directly on the cluster hardware—no installed operating system or preexisting management server required. It collected the cluster’s intent once, validated it, then built the first operating system and generated the infrastructure needed to bring the rest of the fleet online.

One workflow, several deployment models

The tool supported diskless nodes, local-disk installation, partially diskless systems, and a bootable-diskless fallback. It could configure a gateway or flat network, generate host identities and IP assignments, integrate DNS/NIS/NTP, build the node filesystem, configure security policy and monitoring/auditing services, and prepare a backup head node.

Deployment modes
  • Diskless only
  • Partial disk — passive or forced
  • Bootable diskless fallback
  • Local disk via kickstart

Node onboarding
  PXE request → capture MAC → assign hostname/IP → update DHCP → boot image

Provisioning the cluster in parallel

The first node began building the cluster image and services, but the rest of the rack did not have to wait for it to finish. As soon as the first node could serve the image, additional nodes started in diskless mode and became operational. They could then build and configure their local disks in the background while continuing to run.

The builder detected new clients, assigned hostnames and addresses from their MAC information, updated DHCP, and kept enrolling machines as they appeared. The result turned a serial install process into an overlapping cluster build.
