A private CDN crossed with a federated filesystem

Imagine securely browsing a Dropbox folder, an S3 bucket, a cloud drive, institutional data, and storage attached to a computer at home as one continuous collection—available wherever it was needed.

Syndicate presented that common namespace while gateways connected existing storage systems and caches. The data could remain under different owners and in different locations, but applications saw one coherent read/write volume with end-to-end security and application-defined rules.

Large files moved at block level

Each file was divided into configurable blocks with immutable, cacheable identities. If a large file changed slightly, readers could reuse unchanged blocks and retrieve only the new ones instead of transferring the entire file again. CDN-style caching placed frequently read blocks closer to the compute that needed them.

A storage fabric rather than another silo Syndicate combined data locality, cloud durability, local-disk performance, and a shared namespace without requiring users to migrate everything into a new central service.

The platform also needed a new development model

A system with gateways, packages, distributed tests, containers, and multiple storage backends is difficult to reproduce locally. I built an integrated CI, deployment, performance-analysis, and debugging workflow so evidence from an automated failure could become a live diagnostic session.
